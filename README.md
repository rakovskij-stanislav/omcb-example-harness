# OMCBench triage harness

Неоптимальный навайбкоженный харнесс для домашнего задачния PT Start 2026.

Задание для участников: оттриажить с помощью маленькой модели сабсет из 60 пакетов:

```bash
python harness.py /path/to/open-malicious-code-benchmark \
  --endpoint http://127.0.0.1:1234/v1 \
  --model minicpm5-1b \
  --packages-file samples/balanced-60.txt \
  --output runs/minicpm-balanced60
```

Этот харнесс предложен в качестве примера. Участники вправе использовать свой.

---


Простой последовательный runner на Python 3.11+ без внешних зависимостей.
Читает `results/manifest.csv` и архивы из `packages/` в локальном клоне
[open-malicious-code-benchmark](https://github.com/False-Positive-Community/open-malicious-code-benchmark).
Ожидает манифест на 800 релизов. До начала запросов проверяет уникальность
выбранных релизов и наличие их архивов.

## Запуск

```bash
# При необходимости авторизации: задайте OPENAI_API_KEY в окружении.
python harness.py /path/to/open-malicious-code-benchmark \
  --endpoint http://127.0.0.1:8000/v1 \
  --model openbmb/MiniCPM5-1B \
  --output runs/minicpm5-1b
```

`--endpoint` принимает корень сервера (автоматически добавляется `/v1`), API base URL с `/v1` либо полный URL
`/v1/chat/completions`. `--model` должен совпадать с именем модели,
которое обслуживает сервер. Каталог `--output` должен быть новым.
Без этого параметра используется `runs/YYYYMMDD-HHMMSS`.

Сервер должен поддерживать Chat Completions, `tools` и структурированные
`tool_calls` (включая настроенный для модели tool-call parser, если он нужен
вашему серверу). Просто выдавать текст с названием инструмента недостаточно.
Настройте сервер так, чтобы превышение контекстного окна возвращало ошибку,
а не молча обрезало историю: клиент не может обнаружить скрытое обрезание.
Модель запускается отдельно; харнесс не устанавливает зависимости модели
или исследуемых пакетов.

Для первых 50 релизов добавьте `--limit 50`. Релизы обрабатываются последовательно,
строго в порядке манифеста, без перемешивания и балансировки классов.

```bash
python harness.py /path/to/open-malicious-code-benchmark \
  --endpoint http://127.0.0.1:1234/v1 \
  --model minicpm5-1b \
  --limit 50 \
  --output runs/minicpm-first50
```

Адрес и имя модели в примере замените на свои. В консоли прогресс будет
отображаться как `[1/50]` … `[50/50]`. Ограничение общее для обеих экосистем,
а не по 50 пакетов на каждую. Первые K строк могут содержать только одну
экосистему или один класс; такая пачка не обязательно представляет весь датасет.

Метрики рассчитываются только по выбранной пачке; правило исключения неуспешных
триажей из precision/recall/F1 сохраняется. Если в пачке нет одной из экосистем,
для неё будут `total=0` и нулевые метрики — это отсутствие оценки.
Без `--limit` и `--packages-file` обрабатываются все 800 релизов; значение
`--limit` больше 800 выбирает все.
Значение должно быть положительным целым числом.

### Произвольный список и сбалансированная пачка

Параметр `--packages-file` принимает UTF-8 текстовый файл: на каждой строке
точное имя архива из колонки `folder_name` в `results/manifest.csv`, включая
расширение, без префикса `packages/`. Например:

```text
tinysegmenter-0.4.tar.gz
pyperclip-1.9.0.tar.gz
```

Пакеты сканируются последовательно **в порядке строк файла**. Пустые строки
пропускаются, пробелы по краям удаляются; поддерживаются CRLF и UTF-8 BOM.
Комментарии не поддерживаются. Пустой список, дубликаты, неизвестные имена
или отсутствие выбранного архива завершают запуск ошибкой до запросов к модели.
Архивы, не входящие в список, не требуются. `--packages-file` и `--limit`
взаимоисключающие.

Готовый список [`samples/balanced-60.txt`](samples/balanced-60.txt) содержит:

| Экосистема | benign | malicious | Всего |
| --- | ---: | ---: | ---: |
| PyPI | 15 | 15 | 30 |
| npm | 15 | 15 | 30 |
| Всего | 30 | 30 | 60 |

В каждой из четырёх групп случайно выбраны 15 релизов без повторов
(`random.Random(42)`, группы в порядке PyPI benign, PyPI malicious, npm benign,
npm malicious). Группы чередуются по одному релизу; итоговый список зафиксирован
в файле и при запуске не пересоздаётся. Метки берутся из локального манифеста.

```bash
python harness.py /path/to/open-malicious-code-benchmark \
  --endpoint http://127.0.0.1:1234/v1 \
  --model minicpm5-1b \
  --packages-file samples/balanced-60.txt \
  --output runs/minicpm-balanced60
```

Прогресс — `[1/60]` … `[60/60]`. Метрики считаются только по этой пачке,
отдельно для 30 PyPI и 30 npm релизов. Неуспешные триажи по-прежнему отражаются
в `failed` и `coverage`, а precision/recall/F1 считаются по валидным вердиктам.

Дополнительные параметры:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--limit` | все 800 | Первые K релизов из манифеста |
| `--packages-file` | не задан | Сканировать архивы из текстового списка в порядке строк |
| `--max-turns` | 10 | Ходы расследования до принудительного запроса вердикта |
| `--max-tokens` | 4096 | Максимум генерируемых токенов на один ответ, не размер контекстного окна |
| `--timeout` | 300 | Таймаут HTTP-запроса в секундах |

## Локальный web UI для просмотра архивов

```bash
python viewer.py /path/to/open-malicious-code-benchmark --port 8765
```

Откройте `http://127.0.0.1:8765` в браузере на том же компьютере.
Сервер не требует модели, API-ключа, Node.js или сторонних Python-зависимостей.
Остановка — `Ctrl+C`. Порт по умолчанию — 8765. UI использует весь манифест;
параметры `--limit` и `--packages-file` относятся только к CLI-оценке модели.

В интерфейсе доступны:

- список релизов с поиском по имени и фильтром npm/PyPI;
- дерево файлов, переход по директориям и поиск путей по всему архиву;
- пагинация листингов по 100 записей;
- просмотр исходников фрагментами по 16 KiB, предыдущий/следующий фрагмент
  и переход к произвольному байтовому смещению;
- подсветка ключевых слов, строк, комментариев, чисел и имён вызываемых функций
  для Python (`.py`, `.pyi`, `.pyw`) и JavaScript (`.js`, `.mjs`, `.cjs`, `.jsx`);
- перенос строк и HEX-режим для просмотра точных байтов, включая бинарные файлы;
- переключение светлой/тёмной темы в верхней панели. Начальная тема соответствует
  настройке браузера, выбранная тема сохраняется в `localStorage` (если доступен).

Подсветка выполняется локально, без CDN и внешних библиотек. Она лексическая,
а не полноценный парсер: многострочные конструкции на границе фрагментов,
интерполяция строк, регулярные выражения JS и JSX-разметка могут подсвечиваться
приблизительно. В HEX-режиме подсветка отключена. Текст добавляется в DOM только
как текстовые узлы, в том числе внутри цветных `span`, без интерпретации HTML.

В списке релизов и над просмотром файла отображается метка бенчмарка
`benign`/`malicious` из `label_true` в `results/manifest.csv`. Это разметка
датасета, а не вердикт модели. CLI-харнесс по-прежнему не передаёт её модели.
Фрагменты могут разрезать UTF-8 символ: тогда текст содержит символ замены,
а точные байты доступны в HEX. Управляющие символы (кроме табуляции и перевода
строки) и bidi-символы U+202A–U+202E/U+2066–U+2069 показаны как `\uXXXX`.
В текстовом просмотре переносы CRLF и одиночные CR отображаются как обычный
перевод строки, без `\u000d`. Исходные байты, смещения и HEX не изменяются.
Пути отображаются в таком же виде; обращения к архиву используют исходное имя.

Сервер читает архивы через тот же `Archive`, что и харнесс, без распаковки
на диск. Симлинки скрыты и не разыменовываются. Содержимое файлов возвращается
как JSON и выводится через `textContent`: HTML, SVG и JavaScript не становятся
разметкой или скриптами страницы. Нет загрузки пакетов на сервер, кнопок запуска,
скачивания оригиналов или HTML-превью; сырой архив и пути хоста не раздаются HTTP-сервером.

Сервер слушает только `127.0.0.1`, проверяет `Host` и `Origin`, не разрешает
CORS и требует специальный заголовок для API-запросов. Страница использует CSP,
`nosniff`, запрет встраивания во фреймы и запрет кеширования ответов.
Интерфейс работает без CDN и внешних запросов. Он предназначен для локальной
работы, без аутентификации и сетевой публикации. Это уменьшает риск случайного
запуска образцов, но не заменяет VM: парсеры архивов всё равно обрабатывают
недоверенные данные, а пользователь может вручную скопировать и выполнить код.

## Инструменты модели

Каждый релиз получает новую историю с system prompt и заданием. Истинная метка
и манифест модели не передаются. Между релизами история не переносится.
Системный промпт объясняет, что архив уже подключён к инструментам, и требует
начать с `list_path({"path": ""})`, не запрашивая у пользователя путь на хосте.

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `list_path` | `path`, необязательный `page=0` | Непосредственные файлы и подкаталоги указанной директории |
| `list` | `page` | Все обычные файлы архива рекурсивно |
| `read_bytes` | `path`, `m`, `k` | До `k` байтов файла начиная со смещения `m` |
| `send_verdict` | `verdict`, `reasoning` | Завершение с `benign`/`malicious` и непустым текстом обоснования |

Корень архива — `""` или `"."`. Пути относительные, с `/`.
Страницы и байтовые смещения начинаются с нуля. Размер страницы — 100 записей;
ответ содержит `total` и `next_page` (`null` на последней странице).
Порядок лексикографический. `read_bytes` разрешает `1 <= k <= 16384` и возвращает
`bytes_read`, `size`, `eof` и UTF-8 `text`. Если выбранные байты не являются
валидным UTF-8, дополнительно возвращается их точное представление `base64`,
а в `text` используются символы замены. Смещения относятся к исходным байтам,
а не символам. Ошибка аргументов возвращается модели как ответ инструмента.

Первый валидный `send_verdict` немедленно завершает триаж; дополнительные
вызовы после него не выполняются. Текстовый ответ без вызовов инструментов
получает сообщение-напоминание о необходимости вызвать `send_verdict`; диалог
продолжается в пределах `--max-turns`, после чего запрашивается обязательный
вердикт. При невалидном `send_verdict` модель
получает пояснение ошибки и формат аргументов. После второй ошибки валидации
за весь триаж он завершается со статусом `failed` и
`error_type=verdict_validation_limit`. История не сокращается и не компактизируется.
HTTP-ошибка превышения контекста (`context_limit`), `finish_reason=length`
(`token_limit`), ошибки API и архивов — неуспешные
триажи. Автоматических повторов запросов нет. Следующий релиз всё равно
обрабатывается. Для успешного завершения необходим именно `send_verdict`.

После `--max-turns` харнесс добавляет сообщение о завершении расследования
и отправляет дополнительный запрос: в `tools` остаётся только `send_verdict`,
а `tool_choice="required"` требует вызова инструмента. Поскольку доступен только
`send_verdict`, модель должна вызвать именно его. Модель должна вынести
вердикт по уже собранным данным и указать ограничения анализа в `reasoning`.
При первой ошибке валидации разрешается исправление, если общий лимит из двух
ошибок ещё не исчерпан. Таким образом, возможны максимум `max_turns + 2`
ответа модели. Ошибки валидации, совершённые до финального этапа, не сбрасываются.

Само достижение лимита ходов больше не создаёт ошибку `turn_limit`.
Сервер должен поддерживать строковый режим `tool_choice="required"`;
объект с именем функции не используется.
Если он возвращает ошибку API, превышен контекст или модель вместо единственного
`send_verdict` возвращает текст/другой инструмент (`protocol_error`), триаж всё
ещё неуспешен. Харнесс не подставляет вердикт самостоятельно и не сокращает
контекст. У успешных результатов `forced_verdict` показывает, был ли вердикт
получен на финальном этапе; `turns` включает дополнительные ответы.

Например, вызов `send_verdict({"verdict": "benign"})` получит ошибку
`Missing required arguments: reasoning`. Модель может исправить вызов:

```json
{"verdict": "benign", "reasoning": "Обоснование по исследованному содержимому файлов"}
```

Счётчик ошибок валидации действует на весь чат, включая несколько вызовов
в одном ответе. После первой ошибки остаётся одна попытка; вторая завершает
триаж. Напоминания после обычного текстового ответа не увеличивают этот
счётчик, но последующие ответы модели расходуют общий лимит ходов.

## Результаты и метрики

В выходном каталоге:

- `config.json` — параметры запуска без API-ключа, включая `limit` и фактическое
  число выбранных релизов `selected_releases`, путь `packages_file`
  и точный упорядоченный список `selected_archives`;
- `results.jsonl` — одна запись на релиз: метка, вердикт/ошибка, обоснование,
  статус и затраченное время; дописывается и сбрасывается после каждого релиза;
- `chats/0001.json`, `0002.json`, … — полные истории запросов и ответов
  для выбранных релизов (50 файлов при `--limit 50`);
- `metrics.json` — итоговые метрики, также печатаются в stdout.

`py` отображается в `pypi`, `js` — в `npm`. Положительный класс — `malicious`.
Для каждой экосистемы отдельно считаются:

```text
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
f1        = 2*TP / (2*TP + FP + FN)
```

**Precision/recall/F1 считаются только по триажам с валидным вердиктом.**
При нулевом знаменателе возвращается 0. Неуспешный триаж не получает
выдуманную метку benign/malicious и не включается в confusion matrix.
Рядом обязательно сохраняются `total`, `completed`, `failed`, `coverage`,
число ошибок по истинному классу и причины ошибок. `total` — число выбранных
релизов данной экосистемы, `coverage = completed / total` (0 при `total=0`).
Сравнивайте F1 вместе
с coverage: высокий F1 на небольшой доле завершённых релизов не означает
успешную оценку всего датасета. Скрипт заканчивается с кодом 0, если обработал
всю выбранную пачку и записал отчёт, даже если отдельные триажи завершились ошибками.
Возобновление прерванного запуска в этой версии не реализовано.

## Обращение с архивами

ZIP/WHL и TAR/TAR.GZ/TGZ читаются средствами стандартной библиотеки, без
распаковки на диск, установки, импорта и исполнения содержимого. Инструменты
не имеют доступа к произвольным путям хоста. Архивы с traversal-путями,
hardlink, специальными файлами, дубликатами нормализованных имён
или конфликтами файл/директория отклоняются с неуспешным триажем.
Символические ссылки полностью игнорируются: не отображаются в `list` и
`list_path`, не читаются через `read_bytes` и не разыменовываются. Остальные
обычные файлы такого архива доступны для анализа.
Лимиты: 100 000 записей, 512 MiB на файл и 4 GiB суммарного заявленного
распакованного размера. Чтение со смещением в сжатом файле может требовать
повторной декомпрессии; эти ограничения не являются полноценной песочницей
или жёстким ограничением CPU/RAM. Для оригинального вредоносного датасета
используйте изолированную VM, как и для других анализаторов недоверенных архивов.

Содержимое прочитанных файлов передаётся указанному endpoint и сохраняется
в истории чата как недоверенный текст. Не выполняйте код из этих историй.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Тесты используют синтетические архивы и локальный HTTP-сервер на `127.0.0.1`.
Проверяются чтение TAR/ZIP, пагинация, байтовые смещения, опасные пути и ссылки,
tool loop, напоминания, лимит ошибок валидации вердикта, завершения по лимитам
и метрики. Интеграционная проверка выполняет полный CLI-прогон из 800 независимых
чатов, ограниченный прогон первых 50 релизов и прогон произвольного списка
через mock endpoint; проверяет порядок пакетов, ошибки выбора и метрики пачки.
Реальная модель и скачивание датасета не требуются.

Для web UI дополнительно проверяются HTTP-маршруты, пагинация и поиск, чтение
фрагментов, скрытие симлинков, отклонение обхода путей и межсайтовых запросов,
заголовки защиты и выдача потенциально активного HTML только как JSON-данных.
